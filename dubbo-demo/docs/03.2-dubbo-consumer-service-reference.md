# dubbo-consumer-service-reference

看完 Provider 的服务导出与注册，接下来看看 *Dubbo 中的消费者如何从注册中心获取到对应的远程服务调用数据？*

## 服务引用

直接定位到 `org.apache.dubbo.config.deploy.DefaultModuleDeployer.referServices`

```java
private void referServices() {
    // 遍历本地配置中心的每一个服务引用
    configManager.getReferences().forEach(rc -> {
        // ...
        referenceCache.get(rc, false); // 获取
        // ...
    });
}
```

先是遍历本地配置中心的每一个服务引用，然后逐个获取服务引用。来到 `org.apache.dubbo.config.utils.SimpleReferenceCache.get(org.apache.dubbo.config.ReferenceConfigBase<T>, boolean)`

```java
public <T> T get(ReferenceConfigBase<T> rc, boolean check) {
    String key = generator.generateKey(rc);
    Class<?> type = rc.getInterfaceClass();
    boolean singleton = rc.getSingleton() == null || rc.getSingleton();
    T proxy = null;
    // Check existing proxy of the same 'key' and 'type' first.
    if (singleton) {
        proxy = get(key, (Class<T>) type);
    }
    if (proxy == null) {
        List<ReferenceConfigBase<?>> referencesOfType = ConcurrentHashMapUtils.computeIfAbsent(
                referenceTypeMap, type, _t -> Collections.synchronizedList(new ArrayList<>()));
        referencesOfType.add(rc);
        List<ReferenceConfigBase<?>> referenceConfigList = ConcurrentHashMapUtils.computeIfAbsent(
                referenceKeyMap, key, _k -> Collections.synchronizedList(new ArrayList<>()));
        referenceConfigList.add(rc);
        proxy = rc.get(check);
    }
    return proxy;
}
```

接下来看到 `org.apache.dubbo.config.ReferenceConfig.init(boolean)`

```java
protected void init(boolean check) {
    // ...
    Map<String, String> referenceParameters = appendConfig();
    // ...
    ref = createProxy(referenceParameters);
    // ...
}
```

简单点来理解，`ReferenceConfig` 是一个服务引用配置类，Consumer 先拿到引用服务的信息，然后调用 `createProxy` 方法，创建一个对应的代理对象，后续执行远程服务的方法就是通过这个代理对象来进行调用的。

创建代理对象之后需要从注册中心 Subscribe Provider 的相关信息。

流程就来到 `org.apache.dubbo.registry.support.FailbackRegistry.subscribe`

如果使用的是 Zookeeper 来作为注册中心，接下来就会进入 `org.apache.dubbo.registry.zookeeper.ZookeeperRegistry.doSubscribe`，这个方法的签名如下

```java

public void doSubscribe(final URL url, final NotifyListener listener) {}
```

需要传入一个 `NotifyListener` 作为监听器，在 Provider 有变化的时候会调用这个监听器。比如 Provider 实例上线或者下线，都会通过这个监听器来通知消费者。

## 总结

1、消费者启动的时候会根据引用的服务信息创建对应的代理对象来调用远程服务。
2、根据不同的注册中心，会调用不同的 `Registry` 实现类，比如 Zookeeper 注册中心会调用 `ZookeeperRegistry` 的 `doSubscribe` 方法，来监听服务提供者或者配置的变化。
