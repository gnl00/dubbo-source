# dubbo-consumer-service-reference

看完 Provider 的服务导出与注册，接下来看看 *Dubbo 中的消费者进行服务引用的流程*

Dubbo 消费者进行服务引用的方式有三种：

- 第一种是引用本地 (JVM) 服务
- 第二是通过直连方式引用远程服务
- 第三是通过注册中心引用远程服务

不管是哪种引用方式，最后都会得到一个 Invoker 实例。如果有多个注册中心，多个服务提供者，会得到一组 Invoker 实例，此时需要通过集群管理类 Cluster 将多个 Invoker 合并成一个实例。

合并后的 Invoker 实例已经具备调用本地或远程服务的能力了，但并不能将此实例暴露给用户使用，这会对用户业务代码造成侵入。此时框架还需要通过代理工厂类 (ProxyFactory) 为服务接口生成代理类，并让代理类去调用 Invoker 逻辑。

## 服务引用

直接定位到 `org.apache.dubbo.config.deploy.DefaultModuleDeployer.referServices`

```java
private void referServices() {
    // 遍历本地配置中心的每一个服务引用
    configManager.getReferences().forEach(rc -> {
        // ...
        referenceCache.get(rc, false); // 获取
        // ...
    });
}
```

先是遍历本地配置中心的每一个服务引用，然后逐个获取服务引用。顺着调用栈往下


来到 `org.apache.dubbo.config.ReferenceConfig.init(boolean)`

```java
    // ...
    // 获取代理配置
    Map<String, String> referenceParameters = appendConfig();
    // ...
```

---

### Invoker

从字面意思上来看，createProxy 似乎只是用于创建代理对象的。但实际上并非如此，该方法还会调用其他方法构建以及合并 Invoker 实例。

```java
private T createProxy(Map<String, String> referenceParameters) {
    // ...
    createInvoker();
    // ...
    // create service proxy
    return (T) proxyFactory.getProxy(invoker, ProtocolUtils.isGeneric(generic));
}
```

Invoker 是 Dubbo 的核心模型，代表一个可执行体。在服务提供方，Invoker 用于调用服务提供类。在服务消费方，Invoker 用于执行远程调用。Invoker 是由 Protocol 实现类构建而来。

Invoker 创建完毕后，接下来要做的事情是为服务接口生成代理对象。有了代理对象，即可进行远程调用。代理对象生成的入口方法为 ProxyFactory 的 getProxy。

### Proxy


跟着调用栈往下 `org.apache.dubbo.rpc.proxy.javassist.JavassistProxyFactory.getProxy`

```java
public <T> T getProxy(Invoker<T> invoker, Class<?>[] interfaces) {
    try {
        return (T) Proxy.getProxy(interfaces).newInstance(new InvokerInvocationHandler(invoker));
    } catch (Throwable fromJavassist) {} catch (Throwable fromJdk) {}
}
```

通过 Proxy 的 getProxy 方法获取 Proxy 子类，然后创建 InvokerInvocationHandler 对象，并将该对象传给 newInstance 生成 Proxy 实例。InvokerInvocationHandler 实现 JDK 的 InvocationHandler 接口，具体的用途是拦截接口类调用。

---

简单点来理解，`ReferenceConfig` 是一个服务引用配置类，Consumer 先拿到引用服务的信息，然后调用 `createProxy` 方法，创建一个对应的代理对象，后续执行远程服务的方法就是通过这个代理对象来进行调用的。

创建代理对象之后需要从注册中心订阅 Provider 的相关信息。

流程就来到 `org.apache.dubbo.registry.support.FailbackRegistry.subscribe`

如果使用的是 Zookeeper 来作为注册中心，接下来就会进入 `org.apache.dubbo.registry.zookeeper.ZookeeperRegistry.doSubscribe`，这个方法的签名如下

```java

public void doSubscribe(final URL url, final NotifyListener listener) {}
```

需要传入一个 `NotifyListener` 作为监听器，在 Provider 有变化的时候会调用这个监听器。比如 Provider 实例上线或者下线，都会通过这个监听器来通知消费者。

---

## 总结

1、消费者启动的时候会根据引用的服务信息创建对应的代理对象来调用远程服务。
2、根据不同的注册中心，会调用不同的 `Registry` 实现类，比如 Zookeeper 注册中心会调用 `ZookeeperRegistry` 的 `doSubscribe` 方法，来监听服务提供者或者配置的变化。
