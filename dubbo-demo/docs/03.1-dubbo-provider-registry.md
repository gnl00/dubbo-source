```java
                .metadataReport(new MetadataReportConfig(ZOOKEEPER_URL))
```

```java
private void exportServiceInternal(ServiceConfigBase sc) {
    ServiceConfig<?> serviceConfig = (ServiceConfig<?>) sc;
    if (!serviceConfig.isRefreshed()) serviceConfig.refresh(); // 如果没刷新配置，则刷新
    if (sc.isExported()) return;
    if (exportAsync || sc.shouldExportAsync()) { // 异步导出，直接跳过，一般不配置
        ExecutorService executor = executorRepository.getServiceExportExecutor();
        CompletableFuture<Void> future = CompletableFuture.runAsync(
                () -> {
                    try {
                        if (!sc.isExported()) {
                            sc.export();
                            exportedServices.add(sc);
                        }
                    } catch (Throwable t) {
                        logger.error(
                                CONFIG_FAILED_EXPORT_SERVICE,
                                "",
                                "",
                                "Failed to async export service config: " + getIdentifier() + " , catch error : "
                                        + t.getMessage(),
                                t);
                    }
                },
                executor);
        asyncExportingFutures.add(future);
    } else {
        if (!sc.isExported()) {
            sc.export(RegisterTypeEnum.AUTO_REGISTER_BY_DEPLOYER); // 直接看到这里，ServiceConfig 执行自己的导出逻辑
            exportedServices.add(sc);
        }
    }
    if (serviceConfig.hasRegistrySpecified()) registryInteracted = true;
}
```

继续往下

```java
public void export(RegisterTypeEnum registerType) {
    if (this.exported) return;
    if (getScopeModel().isLifeCycleManagedExternally()) {
        // prepare model for reference
        getScopeModel().getDeployer().prepare();
    } else {
        // ensure start module, compatible with old api usage
        getScopeModel().getDeployer().start(); // 兼容 Dubbo 2.x 接口级服务注册
    }

    synchronized (this) {
        if (this.exported) return;
        if (!this.isRefreshed()) this.refresh();
        if (this.shouldExport()) {
            this.init();
            if (shouldDelay()) { // should register if delay export
                doDelayExport();
            } else if (Integer.valueOf(-1).equals(getDelay())
                    && Boolean.parseBoolean(ConfigurationUtils.getProperty(
                            getScopeModel(), CommonConstants.DubboProperty.DUBBO_MANUAL_REGISTER_KEY, "false"))) {
                doExport(RegisterTypeEnum.MANUAL_REGISTER); // should not register by default
            } else {
                doExport(registerType); // 默认直接调到这里，执行导出操作
            }
        }
    }
    getScopeModel().getDeployer().registerServiceInstance();
}
```

```java
private void exportUrl(URL url, List<URL> registryURLs, RegisterTypeEnum registerType) {
    // export to local if the config is not remote (export to remote only when config is remote)
    if (!SCOPE_REMOTE.equalsIgnoreCase(scope)) {
        exportLocal(url); // 导出本地服务
    }
    // export to remote if the config is not local (export to local only when config is local)
    if (!SCOPE_LOCAL.equalsIgnoreCase(scope)) {
        // ...
        // 导出远程服务

        // ...
    }
}
```

```java
private void doExportUrl(URL url, boolean withMetaData, RegisterTypeEnum registerType) {
    // ...

    // 根据注册的对象引用和接口创建 Invoker
    Invoker<?> invoker = proxyFactory.getInvoker(ref, (Class) interfaceClass, url);
    if (withMetaData) {
        invoker = new DelegateProviderMetaDataInvoker(invoker, this);
    }
    Exporter<?> exporter = protocolSPI.export(invoker);
    ConcurrentHashMapUtils.computeIfAbsent(exporters, registerType, k -> new CopyOnWriteArrayList<>())
            .add(exporter);
}
```

再根据不同的协议来到不同的 `Protocol` 中，比如 `org.apache.dubbo.rpc.protocol.tri.TripleProtocol.export`

```java
public <T> Exporter<T> export(Invoker<T> invoker) throws RpcException {
    URL url = invoker.getUrl();
    String key = serviceKey(url);
    // create exporter
    AbstractExporter<T> exporter = new AbstractExporter<T>(invoker) {
        @Override
        public void afterUnExport() {
            // unregister grpc request mapping
            pathResolver.unregister(invoker);
            // unregister rest request mapping
            if (REST_ENABLED) {
                mappingRegistry.unregister(invoker);
            }
            // set service status to NOT_SERVING
            setServiceStatus(url, false);
            exporterMap.remove(key);
        }
    };
    exporterMap.put(key, exporter);
    // add invoker
    invokers.add(invoker);
    // register grpc path mapping
    pathResolver.register(invoker);
    // register rest request mapping
    if (REST_ENABLED) mappingRegistry.register(invoker);
    // set service status to SERVING
    setServiceStatus(url, true);
    // init server executor
    ExecutorRepository.getInstance(url.getOrDefaultApplicationModel())
            .createExecutorIfAbsent(ExecutorUtil.setThreadName(url, SERVER_THREAD_POOL_NAME));
    // bind server port
    bindServerPort(url); // 创建一个 NettyServer 用来处理远程调用请求
    // optimize serialization
    optimizeSerialization(url);
    return exporter;
}
```

最终将 Provider 提供的服务绑定到一个 `org.apache.dubbo.remoting.transport.netty4.NettyHttp3Server` 服务中，来接受处理远程调用请求。

上面就是服务导出的基本流程。

---

有时候我们只是想本地启动服务进行一些调试工作，我们并不希望把本地启动的服务暴露出去给别人调用。此时，我们可通过配置 export 禁止服务导出：

```xml
<dubbo:provider export="false" />
```

## 源码总结

### 1. 整体流程概览

Dubbo 服务导出和注册的完整流程分为三个阶段：

**阶段一：服务导出前置准备**
- 配置加载与刷新（ServiceConfig.refresh）
- 参数校验与 URL 组装（doExportUrlsFor1Protocol）
- 确定导出协议和注册中心

**阶段二：服务导出**
- 本地导出：导出到 JVM 内部（InjvmProtocol）
- 远程导出：
  1. 创建 Invoker（ProxyFactory.getInvoker）
  2. 通过 Protocol 链导出服务（RegistryProtocol → TripleProtocol）
  3. 创建 Exporter 管理 Invoker 生命周期
  4. 启动网络服务器（NettyServer）

**阶段三：服务注册**
- 从 Exporter 中提取注册信息
- 向注册中心注册服务（ZookeeperRegistry.doRegister
- 注册元数据到元数据中心
- 发布服务实例（应用级服务发现）

### 2. 核心概念与职责

| 概念 | 职责 | 关键实现 |
|------|------|---------|
| **Invoker** | 封装服务调用逻辑的执行器，是 Dubbo 核心模型 | DelegateProviderMetaDataInvoker |
| **Exporter** | 管理 Invoker 的生命周期，负责服务的注册与注销 | RegistryProtocol.ExporterChangeableWrapper |
| **Protocol** | 协议层，负责服务的导出（export）和引用（refer） | TripleProtocol, DubboProtocol |
| **Registry** | 注册中心，实现服务的注册、订阅、查询 | ZookeeperRegistry, NacosRegistry |
| **URL** | 统一资源定位符，贯穿整个流程，携带所有配置信息 | tri://192.168.1.1:20880/... |

### 3. 关键设计模式

**SPI 扩展机制**
- Dubbo 自定义 SPI 实现，支持依赖注入、AOP、自适应扩展
- 示例：Protocol、Registry、LoadBalance 都是通过 SPI 加载

**Wrapper 模式（装饰器模式）**
- Protocol 的多层包装：InvokerCountWrapper → ProtocolSerializationWrapper → ProtocolFilterWrapper → ProtocolListenerWrapper → ProtocolSecurityWrapper → RegistryProtocol
- 每一层负责不同的横切关注点（计数、序列化、过滤、监听、安全）

**Adaptive 自适应扩展**
- Protocol$Adaptive 根据 URL 参数动态选择具体协议实现
- 示例：根据 url.protocol 选择 TripleProtocol 或 DubboProtocol

**代理模式（动态代理）**
- 使用 Javassist 字节码生成技术创建服务代理
- ProxyFactory.getInvoker 将服务实现包装为 Invoker

### 4. URL 的核心作用

URL 是 Dubbo 中的统一配置载体，贯穿整个服务导出和注册流程：

```
tri://192.168.1.1:20880/org.apache.dubbo.api.demo.DemoService
  ?application=dubbo-demo-api-provider
  &timeout=20000
  &methods=sayHello,sayHelloAsync
  &side=provider
  ...
```

- **协议选择**：url.protocol 决定使用哪个 Protocol（tri、dubbo、rest）
- **服务标识**：interface + version + group 唯一标识一个服务
- **配置传递**：所有配置参数都通过 URL 参数传递
- **注册信息**：URL 直接作为注册信息写入注册中心

### 5. Dubbo 3 应用级服务发现

**传统接口级注册（Dubbo 2.x）**
- 注册中心存储：每个接口对应一个注册节点
- 问题：大规模服务下，注册中心压力大

**应用级服务发现（Dubbo 3.x）**
- 注册中心仅存储：应用名 → 地址列表的映射
- 元数据获取：通过 MetadataService 获取该应用提供的接口列表
- 优势：大幅减少注册中心数据量，提升性能

**额外导出的服务**

除了用户定义的服务（如 DemoService），Dubbo 还会自动导出：

1. **org.apache.dubbo.metadata.MetadataService**
   - 作用：提供元数据查询服务
   - 消费者通过调用此服务获取提供者的接口元数据
   - 支持应用级服务发现

2. **org.apache.dubbo.metadata.MetadataServiceV2**
   - MetadataService 的升级版本

3. **org.apache.dubbo.registry.RegistryService**
   - 作用：
     - Dubbo 2.x 兼容性（双注册机制）
     - 点对点直连（P2P）注册发现
     - 注册中心功能下沉到服务实例
